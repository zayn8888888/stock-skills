# 个股多维分析

## 核心原则

1. **数据先行，结论在后**：每个判断必须有具体数据支撑，不编造、不夸大
2. **多空并陈，不做单边**：同时列出利多 / 利空 / 风险，帮用户建立完整决策框架
3. **拒绝迎合语气**：即使用户倾向某方向（如"是不是利空出尽了"），也要客观列出反驳论据
4. **不出买卖指令**：只提供分析框架和数据，不说"建议买入/卖出"；最终决策权交给用户
5. **标注数据时效**：行情数据标清时点，新闻/公告标清日期，避免用户把旧信息当新信息

## 前置依赖

本 skill **依赖一个能调用富途 OpenAPI 的 skill / 脚本集**（例如社区 `futuapi` skill），自身不包含任何富途脚本。如果 OpenD 未运行，提示用户先启动 OpenD。脚本路径请替换为你本地实际安装位置（例如 `~/.claude/skills/futuapi/scripts/` 或 `skills/futuapi/scripts/`）。

> **关于下文的 `python3 skills/futuapi/scripts/...` 命令**：这些是与 `futuapi` skill 的脚本目录约定对齐的**示例命令**，不是硬性要求。Claude Skill 机制下 skill 之间无法互相函数调用，只能共享"跑某条命令"的约定。如果你用的是其他数据源（yfinance / Alpha Vantage / 自建 MCP server 等），或者脚本名不同，**直接替换下文每个维度里的命令行即可**，只要能返回对应的字段（行情 / K 线 / 估值 / 资金 / 盘口 / 板块 / 期权链），八维度流程都能跑通。

如果用户给出的是中文名或英文简称（如"五粮液"、"JPM"），请映射为富途完整代码。富途代码格式：

- **港股**：`HK.XXXXX`（5 位数字补零，如 `HK.00700` 腾讯、`HK.09988` 阿里）
- **美股**：`US.TICKER`（如 `US.TSLA`、`US.NVDA`、`US.JPM`）
- **A 股沪市**：`SH.XXXXXX`（6 位，如 `SH.600519` 茅台）
- **A 股深市**：`SZ.XXXXXX`（6 位，如 `SZ.000858` 五粮液）
- **期权简写代码**：交给富途脚本 `resolve_option_code.py` 解析，不要手工拼
- **不确定代码时**用 Tavily 或 WebSearch 确认一次，不要猜错代码后继续往下拉数据

## 执行契约（开工前必读）

这是本 skill 的硬约束。**不满足就不要出报告**——宁可告诉用户"数据不全，以下维度缺失"，也不要用"推荐/可选"当借口跳过。

1. **八个维度全部执行**。维度 1-7 是**必做**（无数据源时明确标注"数据不可用"并说明原因）；维度 8 对美股/港股是**必做**，A 股 / 新加坡 / 其他无期权市场必须显式标注"本市场无期权，跳过"——**不允许静默略过**。
2. **能并行的工具一次性并行调用**。数据齐全后再统一输出报告，不要边拉边写。
3. **输出前自检**（写报告前在心里过一遍）：
   - [ ] 8 个维度都有章节？缺失的是否明确写了原因？
   - [ ] 维度 7 的 `futu-news-search` 和 `futu-comment-sentiment` 是否**真的调用过**？（这两个走 HTTP，不依赖 OpenD——若没调用是漏，不是数据源问题）
   - [ ] 维度 7 关键词是否用了**中文公司名**？英文 ticker 在中文媒体源命中率极低
   - [ ] 关键词是否是**高歧义词**（富途/苹果/小米/京东/茅台/Meta 等）？是的话用了"控股/集团/股份"等锚定后缀没有？
   - [ ] 维度 7 结果**相关性是否自检过**？返回结果与目标股票主题相关 <70%（歧义词 <85%）必须换词重搜
   - [ ] 维度 7 出现**零返回**时，是否按 fallback 链跑完（中文译名 → 英文名 → 代号 → 业务标签 → Tavily 社交检索）？是否用热门票测过 API 没坏？是否把"零讨论"作为信号本身写进报告（"散户关注度极低，机构定价为主"），而不是只写"数据缺失"？
   - [ ] `futu-comment-sentiment` 调用结果是否做了**对照测试**（高热票 vs 冷门票）？两者返回高度重合就是命中"keyword 摆设" bug，必须切 Tavily 雪球检索，禁止把首页杂帖当"目标公司情绪"
   - [ ] 新闻条目用的是 **事件标的检验**（被讨论标的=目标公司？），而**不是**用"标题主语"机械判断？投行评级 / 做空报告 / 媒体评论这种 "X：Y XX" 格式（X 是发表方、Y 是标的）必须保留——上一版"主语必须是目标公司"的规则会误剔除最关键的第三方信号
   - [ ] 维度 1/2 出现单日 ≥5% 或累计 ≥10% 异动时，是否做了**「日期+异动方向」反向追溯搜**？这是回答"为什么涨/跌"的核心证据，不能跳
   - [ ] 反向追溯是否打了**至少 3 条并行 query**（方向词 + 投行枚举 + 机构动作），而不是 1 条空手而归就放弃？
   - [ ] 反向追溯是否**直接在主对话用 Tavily**，没有外包给 `Agent` subagent 黑箱？subagent 会把关键词隐藏，主对话失去调试能力
   - [ ] 维度 7 是否带了**显式证伪段**（未发现：做空报告 / SEC 调查 / 诉讼 / 监管处罚），且每条标了"未命中"或"未搜"？
   - [ ] 维度 7 每条新闻是否带了 `[来源 + 日期]`？
   - [ ] 维度 2/4/8 的 anomaly 三件套（technical / capital / derivatives）是否调用？OpenD 离线时这三个会失败，可标注"OpenD 未连接，跳过"，但**不能与维度 7 的两个 HTTP skill 混为一谈**
   - [ ] 期权链是否真的扫了？Top 5 Call/Put OI + P/C 比 + Max Pain 是否都给出？
   - [ ] "综合研判" 是否同时列了利多 / 利空 / 风险 / 关键信号四块？
   - [ ] 数据时点是否标清？

## 分析流程（八维度）

### 维度 1：基础行情（必做）
```bash
python3 skills/futuapi/scripts/quote/get_snapshot.py <CODE> --json
```
提取：现价 / 开盘 / 最高 / 最低 / 昨收 / 成交量 / 成交额 / 涨跌幅 / 振幅。

### 维度 2：技术走势（必做）
```bash
python3 skills/futuapi/scripts/quote/get_kline.py <CODE> --ktype 1d --num 30 --json
```
重点：近 30 日高点 / 低点 / 当前相对位置 / 是否破位 / 量价配合 / 短期均线关系（5/10/20 日可自行计算）。

**额外触发 `futu-technical-anomaly` skill**（拿富途量化引擎已识别的技术信号清单）：MACD 金叉/死叉、RSI 超买/超卖、KDJ、CCI、BOLL 突破、K 线形态等。把它作为 K 线人工解读的**校验源**——若手工判断与异动信号方向冲突，以异动信号优先并在报告中标注；若异动信号为空，说明近期无显著技术拐点，K 线解读维持原结论即可。

### 维度 3：估值与基本面（必做）
```bash
python3 skills/futuapi/scripts/quote/get_stock_info.py <CODE> --json
```
提取：PE-TTM / PB / 股息率 / 总市值 / 流通市值 / 52 周高低 / 换手率。

### 维度 4：资金流向（必做）
```bash
python3 skills/futuapi/scripts/quote/get_capital_flow.py <CODE> --json
python3 skills/futuapi/scripts/quote/get_capital_distribution.py <CODE> --json
```
重点：**主力资金**（超大单+大单）净流入/流出 / 当日分钟级资金变化趋势 / 散户接盘还是出货。

**额外触发 `futu-capital-anomaly` skill** 补两块旧接口拿不到的维度：
- **买卖经纪商榜**（港股专属强信号）：南向席位 vs 国际投行席位的买卖对决，能定位"是谁在买"
- **卖空异动**：沽空数量/比例的突变（与价格走势对照——价跌沽空降 = 空头回补；价涨沽空升 = 顶部博弈）

把这些作为「主力身份识别」的补充章节，单纯净流入/流出方向不变时也要看这两项——同一个净流入数字，南向砸进来和外资砸进来含义完全不同。

### 维度 5：盘口与成交（必做）
盘口和逐笔需要先订阅：
```bash
python3 skills/futuapi/scripts/subscribe/subscribe.py <CODE> --types ORDER_BOOK TICKER
python3 skills/futuapi/scripts/quote/get_orderbook.py <CODE> --num 10 --json
python3 skills/futuapi/scripts/quote/get_ticker.py <CODE> --num 30 --json
```
重点：买卖盘深度对比 / 近 30 笔成交方向占比 / 大单集中度。

### 维度 6：同行对比（必做）
```bash
python3 skills/futuapi/scripts/quote/get_owner_plate.py <CODE> --json
python3 skills/futuapi/scripts/quote/get_plate_stock.py <PLATE_CODE> --limit 20 --json
```
从板块成分股中选 **2-3 家业务相近、市值相近** 的同行，对比 PE-TTM / PB / 股息率 / 当日涨跌幅。

### 维度 7：新闻与事件（必做）

> ⚠️ **强制澄清（避免误判）**：`futu-news-search` 和 `futu-comment-sentiment` 是 **HTTP API skill，与 OpenD 完全无关**——OpenD 离线 / 行情未登录 / 用户未开户 都不影响它们。**禁止以"OpenD 离线"或"接口仅返回行情"为由跳过这两个 skill**。它们直接走 `ai-news-search.futunn.com`，在维度 1-6 的 OpenD 接口失败时反而更需要补它们。在报告里写"未取到中文新闻"前，必须先验证**这两个 skill 是否真的被调用过**——99% 的"未取到"是漏调用而不是 API 真返回空。

**核心原则**：单 query 必漏。Tavily 的 `news` topic 偏英文主流媒体，中文社交媒体、投资人言论、做空报告常在覆盖范围之外。要**并行覆盖四类信号源**，每类至少一条 query：

| 信号源 | 为什么要单独查 | 优先工具 / query 取向 |
|--------|---------------|-----------|
| **官方动态** | 财报、公告、指引、回购、管理层 | **优先调用 `futu-news-search` skill**（中文公告/研报覆盖优于 Tavily，时效快 1-2 天）；Tavily `news` topic 作为英文补充 |
| **投资人与社交媒体** | 知名持仓人喊话、雪球/X 热帖、散户关注度 | **优先调用 `futu-comment-sentiment` skill** 拿牛牛社区情绪温度 + 热帖；Tavily `general` topic 用「公司中文名 + 重仓/加仓/减持/sell put」等动作词补人物 |
| **监管与做空** | 诉讼、调查、停牌、做空报告、禁令 | Tavily：公司名 + 「调查 做空 short report 停牌」，`news` topic，days 拉长到 60 |
| **市场结构**（按市场可选） | 港股：南向/沽空/大行评级；美股：13F/分析师评级 | Tavily 代码 + 市场专属术语；港股的南向/沽空数据已经在维度 4 的 `futu-capital-anomaly` 拿到，这里只补媒体口径 |

**并行执行**：上述工具调用一次性并行触发，不要串行。`futu-news-search` 和 `futu-comment-sentiment` 不依赖 OpenD（HTTP API），即便 OpenD 离线也能跑。

**关键词怎么选**：

**🚨 中文媒体源必须用中文公司名作关键词，不要用英文 ticker。**
- `futu-news-search` 和 `futu-comment-sentiment` 的底层是中文社区/媒体，`keyword=FUTU` / `keyword=NVDA` 命中率会非常低，常见症状是：返回结果与目标股票主题无关（比如查 FUTU 返回小米/海力士的港股杂帖），或新闻流停在 1-2 周前。
- 正确做法：**英文票也用中文公司名**——`富途控股` / `富途` / `英伟达` / `特斯拉` / `苹果`。每只票准备 1 个主名 + 1-2 个常见简称，逐个尝试。
- **结果相关性自检**：拿到结果后扫一眼标题，与目标股票主题相关 < 70% → 立刻换关键词重试，不要把噪声当数据。
- 美股 ADR 还要补一组港股代号（如富途 `00FUTU` / 阿里 `09988`），中文媒体常用港股代号。

**⚠️ 已知 bug：`futu-comment-sentiment` 的关键词搜索不工作**

经实测验证（2026-05），`futu-comment-sentiment` skill 底层调用的 `https://ai-news-search.futunn.com/stock_feed` 接口的 `keyword` 参数**实质上不参与过滤**——无论传 `keyword=NVDA` / `keyword=Lumentum` / `keyword=LITE`，返回的都是同一批"首页热门 feed"（多为港股杂帖：恒指、阿里、腾讯、海力士等），与目标公司无关。

**含义**：
- 之前看似命中的"NVDA / 特斯拉社区情绪"很可能是首页里**恰好提到这些热门票**的副作用，不是真按 ticker 检索出来的
- Lumentum / 任何冷门票永远拿不到真实评论 —— 不是数据缺失，是 endpoint 设计就不支持
- 即使富途客户端的"个股评论 tab"显示有大量讨论，HTTP API 也拿不到（客户端走的是登录态的 `q.futunn.com` 私有接口）

**正确处置**：
1. 调用 `futu-comment-sentiment` 后，**先用一个高确定性热门票 + 一个冷门票对照测试** —— 如果两者返回内容高度重合（同样的港股杂帖），就是命中此 bug，**该次结果整体作废**
2. 立刻切到 Tavily 中文社交检索作为替代源（详见下方 fallback 链第 5 步）
3. 报告里明确标注："富途社区接口当前关键词不工作，散户情绪改用 Tavily 雪球/Reddit 抓取"——别写成"无相关讨论"

这条记录直到 skill 升级修复 keyword 行为之前都有效。

**🚨 零结果 fallback 链（小盘 / 冷门 / 非中概票常见）**：

中文社区 API 命中率与该票在中文散户中的关注度成正比——美股小盘、非中概、纯 B2B 标的（如光模块、半导体设备、生物制药小票）经常出现"零返回"。零返回不等于 API 故障，需要按链路逐级尝试，全部空才能下"零讨论"结论。

**Fallback 链（按顺序尝试，命中即停）**：

| 步 | 关键词形态 | 例子（以 Lumentum / LITE.US 为例） |
|----|-----------|--------------------------------|
| 1 | 中文译名（主名） | `朗美通` |
| 2 | 中文译名（简称 / 别名） | `朗美通光通信` |
| 3 | 英文公司名 | `Lumentum` |
| 4 | 美股代号（去市场前缀 + 加前缀两试） | `LITE` / `LITE.US` |
| 5 | 港股代号（如有 ADR / 二次上市） | 视个股而定 |
| 6 | **业务标签**（绕开公司名搜行业讨论） | `光模块 800G` / `硅光 CPO` / `数据中心光器件` |

第 6 步是关键：当公司本身没有讨论，但**所属赛道有热度**时，业务标签能找到散户对赛道的看法，可作为该公司情绪的代理。报告里需明确标注"无该股直接讨论，引用所属赛道情绪作参考"。

**全链空 → 降级到 Tavily 社交检索**（**鉴于上述 stock_feed bug，这一步实际是主力源而不是兜底**）：

并行打 3 条 query：
```
1. <英文 ticker> OR <英文公司名> site:xueqiu.com           # 中文散户讨论主阵地
2. <英文 ticker> reddit OR stocktwits OR seekingalpha       # 英文散户讨论
3. <中文译名> OR <英文公司名> 雪球 OR 散户 OR 评论 OR 讨论   # 兜底中文 general topic
```

Tavily 这条路对冷门票（Lumentum 之类）反而比富途接口可靠——雪球索引覆盖广，Reddit 的 /r/stocks /r/wallstreetbets 是英文散户主战场。

**全部空 → 把"零讨论"作为信号本身**：

零讨论不是数据缺失，是**强信号**——在报告里写：
- "散户关注度极低：富途中文社区无该股讨论，雪球/Reddit/StockTwits 也无显著样本。该票主要由机构定价，不存在散户情绪驱动溢价。"

这本身是分析价值——告诉用户"这只票不会因散户情绪暴涨暴跌，主要看机构资金流和基本面"。比写"数据缺失"或"无法判断"强一百倍。

**判断"零讨论 vs 数据故障"**：同一 API 用一个高确定性热门票测一次（比如 `腾讯` / `英伟达`），有结果就说明 API 没坏，目标票确实零讨论。这一步在出"零讨论"结论前必做。

**🚨 歧义关键词陷阱（公司名 = 平台名 / 行业词 / 通用词）**：

某些公司名同时是高频通用词或自有平台名，纯字面搜会污染结果：

| 公司 | 歧义来源 | 噪声样例 |
|------|---------|---------|
| 富途控股 | 富途牛牛是它自家平台 | "富途证券：英伟达涨 5%"——主语是英伟达 |
| 苹果 | 也是水果 / 农产品板块 | "山东苹果产地价上涨" |
| Meta | 元宇宙概念词 | "Meta 概念股集体异动"——主语是其他票 |
| 比亚迪 | 比亚迪股份 vs 比亚迪电子 vs 集团下属 | 容易混淆主体 |
| 茅台 | 贵州茅台 + 茅台镇产区 + 茅台系列 | 行业新闻混入 |
| 小米 | 小米集团 vs 小米汽车 vs 农产品 | 业务条线 + 同名农产品 |
| 京东 | 京东集团 vs 京东健康 vs 京东物流 vs 京东方 | 系族公司互相干扰 |

**识别规则**（满足任一项即标记为高歧义词，必须额外过滤）：
1. 公司名同时是它自家产品/平台/App 的名字（富途/京东/苹果/小米都是）
2. 公司名是行业 / 概念 / 通用词的子串（比亚迪 ⊂ 比亚迪电子；茅台 ⊂ 茅台镇）
3. 公司有同名兄弟公司（京东集团 / 京东健康 / 京东物流 / 京东方）

**对策（按优先级）**：

a) **关键词加锚定后缀**：直接用 `富途控股` 而不是 `富途`，`贵州茅台` 而不是 `茅台`，`小米集团` 而不是 `小米`，`京东集团` 而不是 `京东`。后缀（控股/集团/股份/公司）能把搜索锁定在主体上，过滤平台和系族干扰。

b) **事件标的检验（不是发表方主语检验）**：

   ⚠️ **关键澄清**：判断"这条新闻是不是关于目标公司"，看的是**事件标的**（被讨论/被评级/被分析的对象），不是"标题主语"或"发表方"。投行评级、媒体报道、研报、做空报告都是**第三方对目标公司发声**——发表方写在前面是行业惯例，不能因此剔除。

   正确的判断三问：
   1. **被讨论的标的** 是不是目标公司？
   2. 标的描述了 **目标公司的什么事**（业绩/估值/产品/管理层/风险）？
   3. 该信息会不会影响目标公司股价？

   只要这三问任一为是，**保留**。

   **通用判别启发式**（用 `<目标>` 表示目标公司、`<X>` 表示其他主体）：

   | 标题结构 | 解析 | 处置 |
   |---------|------|------|
   | `<X>：<目标> <动作>`（X = 投行 / 媒体 / 监管 / 做空机构） | X 是发表方，**目标是事件标的** | **保留** |
   | `<X> 维持/上调/下调/看空/看多 <目标>，目标价 ...` | X 是评级方，目标是被评级标的 | **保留** |
   | `<X> 做空报告：<目标> ...` | X 是做空机构，目标是标的 | **保留**（最关键负面信号） |
   | `<目标> <自身动作>...`（涨跌 / 财报 / 回购 / 任命 / 退市 / 收购） | 目标即标的 | **保留** |
   | `<目标>平台/App/资讯/研选/解读：<X>` | 目标是发布渠道，标的是 X | **剔除** |
   | `用 <目标> 交易/查行情/下单 ...` | 目标是工具，无事件 | **剔除** |
   | `<兄弟公司> <动作>`（同集团关联公司） | 标的是兄弟公司 | **单列"关联方动态"**，不并入主流 |

   **关键判断**：标题中**对目标公司施加的动词**是哪类？
   - **被动接受类**（被评级、被报道、被调查、被起诉、被处罚、被分析、被做空）→ 目标是接收方，**保留**
   - **主动发布 + 其他标的**（目标 + "解读/推荐/点评/资讯" + 其他票名）→ 目标是发出方而非标的，**剔除**
   - **目标自身动作**（财报、涨跌、产品、治理、资本动作）→ **保留**

   ❌ **禁止仅凭"冒号前的词 ≠ 目标公司"就剔除**——这会把投行评级、做空报告、监管通告等最有价值的第三方信号全部误删。`X：Y ...` 格式里 X 是发表方而非主体，Y 才是要核验的事件标的。

c) **歧义词触发反向核查**：当目标公司命中歧义清单时，**必须**追加一条"主体限定"搜——例如对富途，搜 `富途控股 财报 OR 业绩 OR 美银 OR 摩根 OR ADR`，强制在金融语境里找主体新闻。

d) **歧义词触发后再做相关性自检**：歧义词的"相关性 70%" 阈值要提到 **85%**，因为 30% 噪声里的"富途证券点评 XX"会严重误导后续解读（容易把别的票的事件错配到富途头上）。

**🚨 价格异动反向追溯（绝对必查）**：
当维度 1 / 维度 2 显示**单日 ≥5%** 或**多日累计 ≥10%** 的异动时，**必须**用「日期 + 异动方向 + 公司中文名」反向搜事件——这是用户最关心的"为什么涨/跌"的直接答案。

**🚫 反向追溯不允许外包给 subagent**：必须在主对话**直接调用 Tavily**，不要用 `Agent` 工具包装"查询 XX 暴跌原因"这种模糊任务。原因：subagent 黑箱处理关键词，主对话失去对查询词的控制权——如果 subagent 用了错误关键词（比如只搜"FUTU stock crash" 没搜"美银 富途 Q1"），主对话不知道、无法纠正，就会出现"已搜过但什么都没找到"的假象。**反向追溯关键词必须可见、可调试、可追加**。

**最少 3 条并行查询**（不命中就再加，宁多勿少）：

1. **方向词查询**（基础证据）：
   - 跌：`<公司中文名> <YYYY-MM-DD> 暴跌 OR 跌停 OR 跳水`
   - 涨：`<公司中文名> <YYYY-MM-DD> 大涨 OR 涨停 OR 飙升`

2. **投行 / 研报枚举查询**（高频催化）：
   暴跌前一天到当天，投行报告是常见导火索。即便没有先验线索，也要打一条投行专项：
   - `<公司中文名> 美银 OR 摩根士丹利 OR 摩根大通 OR 高盛 OR 瑞银 OR 德银 OR 巴克莱 OR 花旗 OR 富瑞 OR 杰富瑞 报告 OR 下调 OR 上调 OR 看空 OR 看多 <YYYY-MM>`
   - 港股加：`<公司中文名> 中金 OR 中信 OR 招商 OR 国君 OR 海通 OR 广发`
   - 这条命中率比"日期 + 暴跌"高得多——投行评级公告有标题模板，搜得到。

3. **机构动作 / 13F / 大宗交易查询**：
   - `<公司中文名> 减持 OR 清仓 OR 13F OR 大宗交易 OR 套现 <YYYY-MM>`
   - 给出名字的机构动作往往比纯股价新闻更具信号价值

4. **特殊事件兜底（按需追加）**：
   - 监管：`<公司中文名> SEC OR 证监会 OR 处罚 OR 调查 OR 问询`
   - 做空：`<公司中文名> 做空 OR Hindenburg OR Muddy Waters OR Citron OR short report`
   - 财报警示：`<公司中文名> 业绩预警 OR 财报 OR 盈利预警 <YYYY-MM>`
   - 地缘：`<公司中文名> 关税 OR 制裁 OR 退市 OR 中概股`

**关键：不命中不等于不存在**。第一轮全部空手而归时**禁止直接写"未发现催化"**，要先做以下检查：
- [ ] 关键词是不是用了**中文公司名 + 中文动作词**？英文 ticker + 英文 query 在中文媒体源会大量漏掉
- [ ] `futu-news-search` 是不是只看了首页？API 时间倒序排，5/7 关键事件如果发表后被新内容刷下去，要用关键词定向搜而不是看默认列表
- [ ] 是不是只搜了 1 条 query 就放弃？至少要打 3-4 条上面分类的并行 query
- [ ] subagent 是不是黑箱了关键词？把它干掉，主对话直接搜

只有上述四项**全部勾完仍无命中**，才能写"未在公开新闻面找到具体催化，疑为非公开信息驱动"。

这一步必须在 `futu-news-search` 主搜回返的"最新到 X 月 Y 日"之外**单独补打**——常规检索按时间倒序拉 N 条，会错过被掩埋的关键事件帖。

**其他关键词策略**：
- **投资人 / 做空机构名字不是白名单**，是「有谁在这只票上发过声」决定的。先用泛词搜一轮（「知名投资人 重仓 <公司名>」、「short report <公司名>」），看谁跳出来，再定向补查。硬编码名字列表在不同股票上会漏掉当下真正活跃的人。
- 若期权或资金维度出现异常（单 strike OI 极端堆积、大额大宗交易、异常沽空比），用**该异常数字或仓位量**作关键词反向搜——金额/仓位往往比名字更容易命中中文报道。

**报告里一定要单列的事件类型**：
- 财报关键数据、回购分红、指引修订、管理层变动
- 诉讼 / 调查 / 退市风险 / 关税或禁令
- 有名有姓的机构或个人新增/加仓/减仓/清仓 / 期权大额动作
- 空头报告 / 做空比率异常变化
- 港股：南向资金连续 N 日净流入/流出、沽空比率突破阈值
- 美股：13F 大幅增减持、主流投行评级变动

**🚨 显式证伪（必须列）**：
报告维度 7 末尾**必须**显式列出"未发现"项，不允许只列发现的内容就收尾。模板：
```
**未发现**（搜索范围 60 天）：
- 做空报告：未命中
- SEC 调查 / 诉讼：未命中
- 监管处罚：未命中
- 管理层异动：未命中
```
"未发现"和"发现"同等重要——价值投资者最关心的就是"是不是漏了什么坏消息"。如果某项确实**搜过且无结果**，就写"未命中"；如果**未搜**，禁止写"未发现"，必须补搜。

**信源标注规范**：每条新闻必须带 `[来源 + 日期]`，社区情绪条目额外带置信度（雪球热帖含 score / 点赞数）。例：
```
- 2026-05-08 [雪球 kina, score 0.86] BofA 看空 Q1 前瞻：新增账户 -15% YoY
- 2026-05-07 [同花顺] 富途暴跌 14%，创始人身家蒸发 11.88 亿美元
```
没有信源 + 日期的条目 = 未经验证的传闻，不允许进入正式报告。

### 维度 8：期权链扫描（美股/港股必做，A 股/新加坡等无期权市场明确标注跳过）

**触发条件**：美股 / 港股（HK/US 前缀）且正股支持期权；A 股 / 新加坡等无期权市场直接跳过并在报告中标注"本市场无期权，跳过"。

**Step 0（快通道）**：先调用 `futu-derivatives-anomaly` skill 拿富途量化引擎已聚合好的衍生品异动指标——**PCR、IV 异动、期权大单、期权情绪综合信号**，港股还包括**牛熊证街货比例 + 街货价格区间**（旧期权链脚本无法获取）。

**这一步的价值**：
- 节省调用次数：原本要分批订阅 ≤12 合约 × N 批才能拼出 PCR 和 IV skew，快通道一次返回
- 降低幻觉：富途口径的"异常成交"是量化筛过的标签，比手动 Vol/OI > 0.3 阈值更稳
- 港股牛熊证是旧流程完全拿不到的维度，对港股蓝筹（腾讯、阿里、美团等）必看

**何时仍需走 Step 1-3 完整扫描**：
- 用户问"机构布局/对冲流"——需要看具体 strike 的 OI 分布，快通道只给聚合数
- 出现单一 strike 极端堆积疑虑——必须扫宽 ±20% 验证
- 快通道返回"无异常"但用户坚持要看结构——继续完整流程

**步骤**：

```bash
# 8.1 取期权到期日列表
python3 skills/futuapi/scripts/quote/get_option_expiration_date.py <CODE> --json
```

**到期日选择策略**：默认扫 **2 个到期日**（近月 + 次近月），覆盖短期情绪 + Max Pain 结构。出现以下情形之一时，**追加第 3 个到期日**：

| 触发情形 | 追加到期日 | 为什么 |
|---------|-----------|-------|
| 未来 30-60 天内有已知事件（财报 / FDA / 股东投票 / 并购表决 / 重大听证） | 事件后的第一个到期日 | 期权市场在事件到期日会集中定价，不扫会漏掉最关键的方向性仓位 |
| 正股是指数 ETF（SPY / QQQ / IWM / HSI ETF 等）或港股前 20 大蓝筹（腾讯 / 友邦 / 阿里 / 汇丰等） | 最近的季度末到期日（3/6/9/12 月第三个周五） | 机构季度调仓、保护性对冲多挂在季末，不看会完全漏掉机构建仓痕迹 |
| 用户明确问"机构布局 / 对冲流 / 大资金方向" | 最近的季度末到期日 | 用户问的就是中长期结构，近月反映不出来 |

**普通个股（无事件 + 非蓝筹 + 未追问机构布局）只扫 2 个近月**，长尾合约流动性差，噪声大于信号。

```bash
# 8.2 取指定到期日范围的期权链
python3 skills/futuapi/scripts/quote/get_option_chain.py <CODE> --start <EXPIRY1> --end <EXPIRY2> --json
```

**筛选范围（重要）**：**默认值 ±10%/±15% 是不够的**。OI 堆积点经常落在深度 OTM（机构保护位、大额 sell-put 锚定价都在这里），默认窗口会直接漏掉。原则：**扫描范围由数据决定，不由默认值决定**。

1. **先拉整条链的 strike 列表**（`get_option_chain` 只返回代码 + strike，不含 OI）——这一步只看 strike 分布就能判断要扫多宽。港股建议至少 ±20%，美股 ±15% 起步；若 strike 稀疏（每档间隔 >5%），再放宽一档。
2. **分批订阅 + 快照**：单次订阅 ≤12 合约（超出触发"未知股票"错误），用 N 批覆盖完整范围。例如 30 个 strike × 2（C/P）= 60 个合约 → 分 5 批。
3. **先扫 Put 后扫 Call**：支撑位信号通常比阻力位更强（sell-put 集中度 > call 卖方动机），预算有限时先 Put。
4. **扫完看 OI 分布再决定要不要再扩**：如果最外档（±20% 边缘）OI 仍显著，说明市场关注位还在更远处，必须再加一批。反之若 OI 尾部归零就可以收手。

```bash
# 8.3 批量订阅并拉取期权完整数据（OI / IV / Greeks / 买卖盘）
# 分批，每批 ≤12 合约
python3 skills/futuapi/scripts/subscribe/subscribe.py <OPT1..OPT12> --types QUOTE
python3 skills/futuapi/scripts/quote/get_stock_quote.py <OPT1..OPT12> --json
# 重复，直到覆盖 ±20% 全范围
```

**重要**：期权数据**必须用 `get_stock_quote.py`**，不要用 `get_snapshot.py`。snapshot 对期权只返回 `last_price/bid/ask/volume/turnover`，**不含 OI/IV/Greeks**；stock_quote 才返回完整期权字段：`open_interest`（未平仓）/ `implied_volatility`（IV）/ `delta|gamma|theta|vega|rho`（希腊字母）/ `strike_price`（行权价）/ `expiry_date_distance`（距到期天数）/ `last_price` / `volume`。

**为什么非要扫宽**：当 OI 在深度 OTM 出现单点极端堆积时，如果窗口没覆盖到，P/C OI 比、Max OI、IV skew 全部会被带偏，结论可能完全反向。这种堆积可能来自（按常见度递减）：机构保护性对冲、知名投资人 sell-put 建仓、做市商围绕事件预留的库存。任何一类漏掉都会造成"结构性误读"。扫描成本远低于误判成本。

**核心判断指标**：

| 指标 | 计算 | 含义 |
|------|------|------|
| Put/Call OI 比 | Σ Put OI / Σ Call OI | >1 偏空持仓；<0.7 偏多持仓；注意长期结构性对冲会让港股指数 ETF 偏高 |
| Put/Call Vol 比 | 当日 Σ Put Vol / Σ Call Vol | 短期情绪，日内变化比 OI 更敏感 |
| Max OI 行权价 | OI 最大的 Call / Put strike | Call Max OI → 潜在阻力（卖方压盘动机）；Put Max OI → 潜在支撑 |
| 异常成交 | Vol / OI > 0.3 或 Vol > OI | 新开仓方向性押注，注意是否靠近财报/事件 |
| 买卖价差比 | (ask - bid) / mid | <5% 流动性良好；5-15% 一般；>15% 几乎无法交易，数据仅供参考 |
| IV Skew | 同到期日 OTM Put IV − OTM Call IV | 正 skew 越大 → 市场愿付更多保费对冲下行，尾部风险定价偏高 |
| ATM IV | ATM Call 与 Put 的 IV 均值 | 对比 HV（历史波动率）：IV > HV 预期波动扩大；IV < HV 预期平静 |
| Max Pain | 到期时所有期权买方总亏损最小的 strike | 到期日附近股价有向此收敛的统计倾向（非因果，只是结构） |

**质量门槛**（不满足则标注"数据不可信"）：

- 个券 OI = 0 且 Vol = 0 → 跳过，不要参与比例计算
- bid = 0 或 ask = 0 → 报价失效，剔除
- IV = 0 或 > 500% → 计算异常，剔除

**过滤与解读输出**：只给用户看 **Top 5 Call OI + Top 5 Put OI + 异常成交 Top 3**，不要把几十行原始数据倒出来。解读要把数字和股价位置挂钩：
- "Call Max OI 集中在 XXX（现价上方 X%），是主要阻力"
- "IV 24%，较 30 日 HV 18% 高 6pp，市场预期财报后波动显著"
- "Put/Call OI 比 1.4，偏空；但 Put OI 中 XXX 行权价占 45%，可能是机构保护性对冲而非方向性空头"

**单一 strike 极端堆积的识别与追查**：

- **识别标准（取任一）**：
  - 该 strike 的 OI 占同向（全 Call 或全 Put）总 OI 的 **>50%**，或
  - 该 strike 的 OI 是第二大 strike OI 的 **>3 倍**，或
  - 名义金额（OI × 行权价 × lot_size）达到该股流通市值的 **1% 以上**
- **lot_size 必查**：美股期权 1 张 = 100 股，港股 1 张一般 = 100 或 200 股（须从期权合约字段 `lot_size` 读取，不要猜），A 股场内股票期权 1 张 = 10000 股（ETF 期权 10000 份）。lot_size 算错名义金额会差一个数量级。
- **追查动作**：达到识别标准即视为"事件级"仓位，报告必须单独高亮。用当日相关新闻（大额期权、sell put、知名机构动作、做空报告等关键词 + 公司名/代码）反向搜索，挖出背后是谁、为什么、是否已公开表态。

## 常见陷阱

详细解读见 [references/metrics-interpretation.md](references/metrics-interpretation.md)。速记要点：

- **PE 失真**：周期股底部 PE 反而高；会计差错更正后 PE 可能严重失真；亏损股无 PE
- **资金流向仅参考**：单日主力净流入不等于后续上涨，看 3-5 日趋势更可靠
- **盘口可伪造**：大额挂单可能是诱多/诱空，需结合逐笔成交方向验证
- **股息率陷阱**：高股息率可能是股价下跌推高的假象，要看历史分红稳定性
- **成交量零值**：非交易时段 / 停牌股 get_snapshot 会返回 0，不要误判为"无人成交"
- **期权 OI ≠ 方向**：高 Put OI 可能是机构买保险（bullish 对冲）而非看空；判断方向要看新开仓方向（Vol/OI）和 IV skew，单看 OI 容易误读
- **期权 Max Pain 非因果**：只是到期日大量 OI 集中时做市商对冲形成的统计倾向，远离到期日参考价值很低
- **港股期权流动性稀薄**：多数港股期权 bid-ask 价差 >20%，除腾讯/友邦/阿里等极少数标的，数据噪声大于信号

## 什么时候答"不确定"

明确告诉用户**无法判断**，不要硬凑：

- OpenD 未连接 / API 调用失败
- 数据明显异常（PE 负值、成交量为 0）
- 预测性问题（"明天会涨吗"、"一周后多少"）

## 输出调性

- 克制中性，不用"强烈推荐"、"必涨"、"肯定跌"等绝对化表述
- 金额用"亿/万"口径，百分比保留 1-2 位小数
- 关键数据用粗体 / 表格强化，避免大段文字
- 用户只追问某一维度时展开该维度，否则按八维度模板全景输出
