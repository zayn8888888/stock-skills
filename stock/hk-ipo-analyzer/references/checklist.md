# 港股 IPO 输出前自检清单

只在当前输出路径需要时读取本清单。每项状态只能是 `done`、`failed_after_search`、`legal_na`。不能用"需补"、"未完成"、"后续再查"代替执行结果。

## 0. 路径选择

- [ ] 是否已区分 facts-only、市场级日历、单只摘要、暗盘、退出框架、深度报告、保荐人战绩？
- [ ] 是否已识别 IPO 阶段：递表 / 已通过聆讯 / 招股中 / 已定价待上市 / 上市首日 / 上市后 N 天？
- [ ] 未上市公司是否没有编造股票代码？
- [ ] 是否选择满足问题的最小模板？

## 1. Facts-only 轻量答案

适用于"什么时候上市"、"发行价多少"、"招股书链接"、"配售结果出了吗"等事实查询。

- [ ] 是否只回答用户问的字段，没有自动扩展成完整报告？
- [ ] 字段是否来自官方文件、Futu 结构化字段、公司 IR 或明确标注的搜索结果？
- [ ] 涉及 Prospectus / PHIP / Application Proof / Allotment Results 时，是否记录 PDF URL 或来源页面？
- [ ] 缺字段是否写"本次审查中未在官方文件或搜索结果中确认"，并说明已查来源？
- [ ] 是否没有生成 IPO Trade Score 或 Fundamental Holding Score，除非用户明确要求？

## 2. 市场级 IPO 日历

- [ ] 是否调用或尝试调用 `get_ipo_list.py HK --json`？
- [ ] 是否只引用响应中实际存在的字段？
- [ ] 若缺发行价、上市日、申购期、募资额或每手股数，是否用官方/搜索来源补证？
- [ ] 是否使用 Template A，而不是单只 IPO 深度报告？
- [ ] 是否没有给单只标的申购/买入指令？

## 3. 单只 IPO / 报告级输出门控

- [ ] G1 官方文件：是否至少一次官方源搜索？港股是否按 `hkex-documents.md` 查 HKEXnews PDF href？
- [ ] G2 发行结构：发行价/区间、上市/申购日期、募资用途、承销商/保荐人、锁定期/解禁窗口是否确认或标缺？
- [ ] G3 保荐人战绩：近 12/24 个月样本、破发率、上涨率、中位收益是否计算？或是否合法 N/A？
- [ ] G4 同业估值：是否有 3-5 家同业估值锚？不足时是否列出搜索词和原因？
- [ ] G5 上市后交易质量：上市后标的是否核对发行价 vs 当前价、首日收盘、破发状态、成交/换手？未上市时是否 `legal_na`？
- [ ] G6 checklist 自检：是否在综合结论前完成本清单，而不是报告写完后补看？
- [ ] G7 双评分：IPO Trade Score 和 Fundamental Holding Score 是否都已计算？置信度、Preliminary/Final、可能改变评分的缺失数据是否已列出？

## 4. 评分自检

- [ ] IPO Trade Score 是否使用阶段对应权重：Pre-allotment 或 Post-allotment / 首日？
- [ ] IPO Trade Score 7 个因子是否均有 0-10 原始分、权重、加权贡献和证据状态？
- [ ] Fundamental Holding Score 6 个因子是否均有 0-10 原始分、权重、加权贡献和证据状态？
- [ ] `actual`、`proxy`、`failed_after_search`、`legal_na` 是否使用一致？
- [ ] `failed_after_search` 是否没有被重分配权重，而是使用 fallback 分？
- [ ] `legal_na` 是否已按比例重分配到其余适用因子？
- [ ] IPO Trade Score 标签是否匹配 85-100 Elite、70-84 Strong、50-69 Neutral、35-49 Weak、0-34 Very Weak？
- [ ] Fundamental Holding Score 标签是否匹配 80-100 Strong、60-79 Constructive、40-59 Mixed、20-39 Weak、0-19 Very Weak？
- [ ] 评分是否未被转换成直接申购、买入或卖出指令？

## 5. 港股 IPO 核心字段

- [ ] 发行价 / 定价区间是否确认？
- [ ] 上市日 / 申购期是否确认？
- [ ] 募资额 / 募资用途是否确认？
- [ ] 承销商 / 保荐人是否确认？
- [ ] 保荐人战绩是否列出样本数、首日破发率、当前破发率、当前上涨率、首日/当前收益中位数？
- [ ] 保荐人样本不足、行业集中或缺发行价/价格数据时，是否标注样本偏差并剔除缺失样本？
- [ ] 流通盘、基石/战略配售、锁定期/解禁窗口是否确认或明确缺失？
- [ ] 基石投资者名单和锁仓期是否列出？
- [ ] 绿鞋 / 稳价人是否确认？
- [ ] 老股出售是否确认？
- [ ] 回拨机制和最终回拨结果是否确认？
- [ ] 招股书主要风险是否列出 1-3 条？

## 6. 市场需求

只在招股中、已定价待上市、暗盘、首日或深度报告中适用。

- [ ] 公开发售超额认购倍数是否确认？
- [ ] 孖展倍数是否确认或标为 proxy / failed_after_search？
- [ ] 国际配售覆盖倍数是否确认？
- [ ] 配售比例和一手中签率是否确认？
- [ ] Allotment Results 未发布时，是否使用 pre-allotment 权重并标 Preliminary？
- [ ] 缺失需求数据是否标为缺口，而非凭印象估算？

## 7. 模板自检

- [ ] facts-only 是否使用 Template 0 或简洁回答？
- [ ] 市场级日历是否使用 Template A？
- [ ] 单只默认分析是否使用 Template 1？
- [ ] 暗盘 / 首日预测是否使用 Template 2？
- [ ] 退出策略是否使用 Template 3？
- [ ] 深度分析是否使用 Template 4？
- [ ] 简短问题是否没有生成不必要的 16 节报告？
- [ ] 深度分析请求是否没有只输出一页式摘要？

## 8. 判断纪律

- [ ] 是否避免输出"建议申购 / 建议买入 / 必破发 / 必涨 / 稳赚 / 无风险"？
- [ ] 亏损或 pre-revenue 公司是否没有硬套 P/E？
- [ ] 上市不满 90 个交易日时，是否标注技术面/估值分位数据不足？
- [ ] 缺字段是否写"未确认"，没有用估算替代事实？
- [ ] 所有缺口是否都有已执行的搜索词、调用或合法跳过原因？
- [ ] 暗盘是否使用 bear/base/bull 三档情景，而非单点价格预测？
- [ ] 卖出策略是否使用情景化退出框架，而非直接指令？
- [ ] 结论是否使用谨慎标签，并与评分区间一致？

## 9. 跨 skill

- [ ] 用户要成熟股票交易层面的"能不能买 / 是否加仓"时，是否建议调用 `stock-analyzer` 补九维度？
- [ ] 用户要市场热点时，是否转 `market-scanner`？
